## Implemented State Machines

NameNode Federation preserves the 18 stable operations in this order: stop required services; save HDFS/conditional Ranger/Accumulo configs and install HDFS clients; install two NameNodes; install two ZKFCs; start JournalNodes; conditionally start Infra Solr, Ranger Admin, and Ranger Usersync; start existing NameNodes and ZKFCs; format the first new NameNode and ZKFC; start the first pair; bootstrap the second NameNode; start the second pair; restart the exact non-Federation component predicate.

Router Federation uses an explicit four-step flow. Review loads and validates current desired configs, creates `hdfs-rbf-site` when absent, and awaits its PUT before entering progress. Progress rereads the Router topology, registers only missing hosts, verifies registration, reconciles the complete selected Router set to `INSTALLED` with maintenance OFF, starts that complete set, and clears persisted state only after terminal success.

HAWQ Add uses four ordered operations; Remove uses five; Activate uses seven. Every mode is hidden and direct navigation is blocked unless live stack metadata exposes `hawq-site`, `HAWQMASTER`, `HAWQSTANDBY`, the required custom command, and compatible installed topology. Capability loading reacts to stack/version, installed-service, host, component-host, and component-state changes; empty or failed loads terminate with an error and Retry. All HAWQ behavior remains static-only until a compatible historical stack is run.

All progress operations have stable IDs. State, active step, request IDs, task statuses, cluster progress, and owner are written through `/persist` before navigation or the next mutation. A request-status GET failure after an ID is saved preserves the request ID and `IN_PROGRESS` state and exposes `Retry Status Check`; it does not replay that mutation. `Retry Operation` is available only after a local mutation failure or a server-confirmed `FAILED`, `ABORTED`, or `TIMEDOUT` terminal state. A server-accepted mutation whose response is lost before its ID is persisted remains an unknown outcome: the saved `QUEUED` state cannot reconcile it and recovery may resubmit. Another user is blocked; non-404 workflow-load errors are terminal and expose Retry. Exit during progress preserves the checkpoint and explicitly warns that completed server effects are not rolled back.

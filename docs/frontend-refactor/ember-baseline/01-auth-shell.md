## Permission Model

After login, `privileges[].PrivilegeInfo.permission_name` determines the global roles:

- `AMBARI.ADMINISTRATOR` sets `App.isAdmin`.
- `CLUSTER.ADMINISTRATOR` for the current cluster sets both `isAdmin` and `isOperator`.
- Fine-grained actions such as Cluster Operator, Service Administrator, Service Operator, and Cluster User ultimately use `App.isAuthorized(permission)` for authorization.
- A user with only View permissions and no cluster operations permissions enters Views without initializing the full operations pages.

See [13-permissions-flags.md](13-permissions-flags.md) for detailed permission and feature associations.

## Global HTTP Semantics

- All named requests default to the `App.timeout` timeout and `Content-Type: text/plain` to prevent Knox from modifying the JSON body.
- Without a custom error callback, statuses such as 500, 401, 407, and 413 use the global error modal, which displays the method, URL, status, and server message.
- KDC-related 400 errors are recognized and use the Invalid KDC popup instead.
- A request can configure a loading popup; it is shown only after 500ms and cleared on complete.
- An oversized GET is automatically converted to a POST with `X-Http-Method-Override: GET`.

## Placeholders and Boundaries

- `/main/admin/authentication`, `/main/admin/advanced`, and `/main/admin/audit` have outlet routes in `routes/main.js`, but no complete corresponding controller/template was found in the legacy Ember tree. They are marked `PLACEHOLDER` and cannot be treated as confirmed pages that React must reproduce.
- `/main/test` connects only to the `mainTest` outlet in `routes/main.js`; no corresponding controller, template, or view exists in the legacy Ember tree, so it is marked `PLACEHOLDER`. The route fragment remains in the static inventory but does not create a React feature requirement.
- User, group, role, and View instance management is provided by the separate AngularJS Admin Console and is outside this Ember baseline.
